## 1. OpenFreeMap (basemap)

### 1.1 URLs (all checked live)

| What | URL |
|---|---|
| Style | `https://tiles.openfreemap.org/styles/positron` (25 KB JSON) |
| Vector source (TileJSON) | `https://tiles.openfreemap.org/planet` → versioned tiles `https://tiles.openfreemap.org/planet/20260927_080001_pt/{z}/{x}/{y}.pbf`, `maxzoom 14` (overzoomed beyond) |
| Raster hillshade source `ne2_shaded` | `https://tiles.openfreemap.org/natural_earth/ne2sr/{z}/{x}/{y}.png`, `maxzoom 6` |
| Glyphs | `https://tiles.openfreemap.org/fonts/{fontstack}/{range}.pbf` — stacks used: `Noto Sans Regular`, `Noto Sans Bold`, `Noto Sans Italic` |
| Sprite | `https://tiles.openfreemap.org/sprites/ofm_f384/ofm` (`.json`, `@2x.png`) |

The tile URL inside the TileJSON is **versioned** (weekly planet build); always reference the style or
the TileJSON, never a hard-coded tile URL.

### 1.2 Terms

- openfreemap.org: *"Using our public instance is completely free: there are no limits on the number of
  map views or requests. There's no registration, no user database, no API keys, and no cookies."*
  FAQ: *"Is commercial usage allowed? Yes."* No SLA.
- **Attribution is required.** MapLibre adds it automatically for interactive maps; *"if you are using this
  in printed media or video, you must add the following attribution: OpenFreeMap © OpenMapTiles Data
  from OpenStreetMap"* ("the OpenFreeMap part is not required but nice").
  → `MT.theme.attribution.text = "© OpenStreetMap contributors · © OpenMapTiles · OpenFreeMap"` satisfies
  both OpenFreeMap and SPEC §2.5. **Every export (PNG, PPTX, HTML) must draw it on the map.**
- Terms of Service (updated 2026-09-09): service "as-is", may be discontinued without notice; users must not
  *"attempt to collect data from the service in automated ways without permission"*. → Never pre-fetch or
  bulk-download tiles. Rendering a map view for an export (what `MT.render` does) is ordinary use.
- Map data © OpenStreetMap contributors (ODbL).

### 1.3 CORS and canvas safety

Every OpenFreeMap endpoint (style, TileJSON, tiles, glyphs, sprite json/png) answers
`access-control-allow-origin: *`, also to `Origin: null` (checked with curl and in Chrome from `file://`).
Consequence: the WebGL canvas is **not tainted** and `canvas.toDataURL()` works from `file://`
(tech-proof captures succeed). Logos are data URIs for the same reason; an `<img src="logos/x.png">`
loaded from `file://` **does** taint a canvas (`SecurityError` on `toDataURL`, verified) — never draw
file paths on a canvas, always `MT.logos.get(id).badge` / `MT.logos.image(id)`.

### 1.4 Positron layer ids (for M1)

`background`, `park`, `water`, `landcover_ice_shelf`, `landcover_glacier`, `landuse_residential`,
`landcover_wood`, `waterway`, `building`, `tunnel_motorway_casing`, `tunnel_motorway_inner`,
`aeroway-taxiway`, `aeroway-runway-casing`, `aeroway-area`, `aeroway-runway`, `road_area_pier`,
`road_pier`, `highway_path`, `highway_minor`, `highway_major_casing`, `highway_major_inner`,
`highway_major_subtle`, `highway_motorway_casing`, `highway_motorway_inner`, `highway_motorway_subtle`,
`railway_transit`, `railway_transit_dashline`, `railway_service`, `railway_service_dashline`, `railway`,
`railway_dashline`, `highway_motorway_bridge_casing`, `highway_motorway_bridge_inner`, `boundary_3`,
`boundary_2`, `boundary_disputed`, and the symbol layers below.

| Symbol layer | source-layer | Notes |
|---|---|---|
| `waterway_line_label`, `water_name_point_label`, `water_name_line_label` | waterway / water_name | text-field uses `name_en` |
| `highway-name-path`, `highway-name-minor`, `highway-name-major` | transportation_name | street names (`name_en` first → "Petit Thouars Avenue") |
| `highway-shield-non-us`, `highway-shield-us-interstate`, `road_shield_us` | transportation_name | `ref` shields (e.g. "1N") |
| `airport` | aerodrome_label | |
| `label_other`, `label_village`, `label_town`, `label_city`, `label_city_capital`, `label_state`, `label_country_1/2/3` | place | neighbourhood/district names (Lima districts render as small italic caps via `label_other`) |

- **POIs:** positron draws **no POI layers** (the tiles contain a `poi` source-layer, but the style does
  not use it) → nothing to hide. If another OpenFreeMap style (bright/liberty) is ever used, hide every
  layer whose `source-layer` is `poi`.
- **Spanish labels:** positron's text-field is
  `["case", ["has","name:nonlatin"], …, ["coalesce", ["get","name_en"], ["get","name"]]]`, so Lima streets
  come out in English ("Petit Thouars Avenue"). In Peru OSM `name` is already Spanish; the tiles also carry
  `name:es`. Patch after the style loads (proven, `tech-hires-3x-render-es.png` shows
  "Avenida Petit Thouars"):

  ```js
  map.on('style.load', () => {
    for (const layer of map.getStyle().layers) {
      if (layer.type !== 'symbol') continue;
      const tf = map.getLayoutProperty(layer.id, 'text-field');
      if (tf && JSON.stringify(tf).includes('name_en'))
        map.setLayoutProperty(layer.id, 'text-field', MT.theme.basemap.spanishTextField); // coalesce(name:es, name)
    }
  });
  ```
  The ids are also listed in `MT.theme.basemap.labelLayers`. Any symbol layer you add must use one of the
  three Noto Sans stacks (`MT.theme.fonts.mapLabels`) — other fonts do not exist on the glyph server.

## 2. High-resolution PNG of a MapLibre map from `file://` (proven)

Evidence: `tools/test/out/tech-hires-3x-preserve.png` and `tech-hires-3x-render.png` — both
**3000 × 2517 px** for a **1000 × 839 CSS-px** map (the reference frame, aspect 7.75 : 6.5), rendered in
headless Chrome from `file://`, not blank, ~1.0–1.7 s each with SwiftShader.

```js
const map = new maplibregl.Map({
  container,                       // 1000 × 838.7 CSS px, laid out (off-screen is fine, display:none is not)
  style: MT.theme.basemap.style,
  pixelRatio: 3,                   // ← canvas = CSS size × 3
  interactive: false, fadeDuration: 0, attributionControl: false,
  canvasContextAttributes: { preserveDrawingBuffer: true, antialias: true },   // technique A
  bounds / center+zoom: same view as the preview (zoom = MT.geo.zoomForWidth(view.zoomRef, 1000)),
});
map.once('idle', () => {
  const png = map.getCanvas().toDataURL('image/png');   // technique A: buffer preserved
  map.remove();
});
```

- **Technique A — `preserveDrawingBuffer`.** In MapLibre 5 the option lives in
  `canvasContextAttributes` (the old top-level `preserveDrawingBuffer` option is gone). Costs a little
  performance, so use it only on the throw-away export map, not on the interactive one.
- **Technique B — capture inside `render`.** Default context; after `'idle'`, call
  `map.triggerRepaint()` and read the canvas synchronously in the next `'render'` event
  (`map.once('render', () => canvas.toDataURL())`); the drawing buffer is still valid in that tick. Works
  on the interactive map too.
- Wait for **`'idle'`** (style, sprites, glyphs and all tiles loaded, no transition). Apply style patches
  (Spanish labels, district borders, radius layers) before waiting.
- `fadeDuration: 0` avoids half-faded labels in captures.
- **Size limit:** `maxCanvasSize` defaults to **[4096, 4096]**; beyond it MapLibre lowers the effective
  pixel ratio. 1000 × 4 = 4000 px fits (4× is the maximum the UI offers). WebGL limits seen:
  `MAX_RENDERBUFFER_SIZE` 8192 (SwiftShader), 16384 (RTX 4090) — raise `maxCanvasSize` only if needed.
- Compose overlays (borders, radius, leader lines, dots, markers, attribution) on a 2D canvas of the same
  size, drawing in reference units × scale (`scale = canvas.width / 1000`). Text in that canvas must use
  fonts that are loaded (`document.fonts.load(...)` — `MT.data.ready` already loads Instrument Sans,
  Bricolage Grotesque and Carlito).

## 3. WebGL in headless Chrome

Results of `document.createElement('canvas').getContext('webgl2')` + `WEBGL_debug_renderer_info`:

| Flags | Renderer |
|---|---|
| *(none)* on this PC | ANGLE D3D11 — NVIDIA RTX 4090 (real GPU; new headless uses the GPU when present) |
| `--disable-gpu` | ANGLE D3D11 — Microsoft Basic Render Driver (WARP) |
| `--disable-gpu --enable-unsafe-swiftshader` | ANGLE Vulkan — SwiftShader |
| `--use-angle=swiftshader` | ANGLE Vulkan — SwiftShader |
| `--use-angle=swiftshader --enable-unsafe-swiftshader` | ANGLE Vulkan — SwiftShader ✔ (harness default) |

The harness (`tools/test/lib.mjs`, `WEBGL_ARGS`) uses
`--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`: identical software
rendering on every machine (GPU or not, CI included). Since Chrome 137 the automatic SwiftShader
fallback for WebGL is gone, so on GPU-less machines `--enable-unsafe-swiftshader` is what keeps WebGL
alive. Map screenshots therefore do not depend on the developer's GPU.

## 4. Nominatim and Overpass from a `file://` page

A page opened from `file://` has `location.origin === "file://"`, sends **`Origin: null`** and **no
`Referer`**.

### 4.1 Nominatim — works

`fetch()` of `/search` and `/reverse` from `file://` → **HTTP 200** with
`access-control-allow-origin: *` (tech-proof and `net.mjs`: "Av. José Larco 345, Miraflores" →
-12.120754, -77.028956; reverse → "Calle Lima 345, Miraflores"). Implemented in `MT.geo`:
global queue (≥ 1.1 s between request starts, measured 1612 ms for two calls), per-session cache,
`countrycodes=pe`, `accept-language=es`, results normalized to `{lat, lng, label, street, district, …}`.
**Policy for callers:** search only on Enter / button (never as-you-type), geocode imports with
`MT.geo.geocodeBatch` (sequential, progress, cancellable). Do not add an `email=` parameter with
personal data. From GitHub Pages the browser sends `Referer: https://pebrauner.github.io/`, which is
what the Nominatim policy asks for.

### 4.2 Overpass — main instance rejects `file://`; use mirrors there

- `overpass-api.de` answers **HTTP 406 Not Acceptable without CORS headers** when the request has a
  browser User-Agent and **no Referer** → from `file://` Chrome reports
  *"blocked by CORS policy: No 'Access-Control-Allow-Origin' header"* (tech-proof). Isolated with curl:

  | User-Agent | Origin | Referer | Result |
  |---|---|---|---|
  | Chrome | `null` | — | 406 |
  | Chrome | — | — | 406 |
  | Chrome | `https://pebrauner.github.io` | `https://pebrauner.github.io/` | **200** |
  | custom app UA | — | — | **200** |

  A page cannot set `Referer` or `User-Agent`, so **on `file://` overpass-api.de is unusable; on GitHub
  Pages it works.**
- Mirrors that accept `Origin: null` (200 + `access-control-allow-origin: *`):
  `overpass.private.coffee` (35 s for a tiny query, data timestamp 2026-07-15; 504 on another run) and
  `overpass.kumi.systems` (78–172 s, data timestamp 2026-07-28). `maps.mail.ru` returned 504.
  **Mirrors are slow and their data is ~2 months old.**
- **Workaround implemented in `MT.geo`:** `MT.geo.overpassEndpoints()` orders endpoints by context —
  `file://`: private.coffee → kumi → mail.ru → overpass-api.de; `https:`: overpass-api.de first.
  `MT.geo.overpass(query, {signal, timeoutMs, onStatus})` runs **one query at a time**, POSTs a
  form-encoded body (a CORS "simple request": no preflight — do not add custom headers), falls back on
  network/CORS errors, 406, 429 and 5xx, stops on 400 (bad query), and returns
  `{json, endpoint, timestamp}`. Verified end-to-end by `net.mjs` (private.coffee 504 → kumi 200).
- **What the app must do (M3):** show the data date (`timestamp`, e.g. "datos OSM al 28/07/2026") and the
  endpoint in the scan review; keep queries small (split by district/bbox); show progress via `onStatus`;
  and tell users that the freshest scans come from the GitHub Pages version (or from the Node seed
  scripts, which send a proper User-Agent).

## 5. Other `file://` facts (verified in Chrome)

- `window.isSecureContext === true` on `file://`; `showDirectoryPicker`, `showSaveFilePicker` and
  `showOpenFilePicker` exist → "Guardar en carpeta" and Ctrl+S project saving work locally in
  Chrome/Edge. Elsewhere `MT.storage.saveToFolder` / `MT.project.save` fall back to downloads.
- `fetch('data/chains.js')` from `file://` → `TypeError: Failed to fetch` — hence data as script globals.
- Injected classic `<script>` tags load from `file://` (SheetJS and PptxGenJS are lazy-loaded this way).
- IndexedDB and localStorage work on `file://`, **but every local HTML page shares the single `file://`
  origin**: two copies of the app folder on the same PC share the same local overlay and autosave. Our
  database is named `mapa-tiendas` and all localStorage keys start with `mt.` to avoid clashes with
  other local pages.
- Fonts are inlined as data URIs (`vendor/fonts/fonts.css`): `@font-face` URLs are CORS-mode requests
  whose `file://` rules differ between browsers; data URIs load everywhere, need no extra request and are
  ready for canvas text as soon as `document.fonts.load()` resolves.
